# Tape Data Product rewrite

This repository is in an active rewrite toward the new one-second base measurements and feature views. Before working on the rewrite, read `planning/rewrite/README.md`, `planning/rewrite/phases.md`, and the current phase specification. Those files define the target and implementation sequence; do not infer the new contract from the legacy code.

`README.md` is the historical research report. The tracked `docs/` tree documents implemented, reviewable behavior. Track durable specifications, accepted decisions and concise completion records in `planning/rewrite/`. Keep raw logs, machine snapshots, temporary handoffs, private catalogs and credentials in ignored `local_docs/` or `private/`. When a rewrite phase is accepted, update the relevant tracked documentation to describe what is actually implemented; do not present planned behavior as current behavior.

The new feature product replaces the legacy compact 18-field, 60s/300s design as the target architecture. Do not carry legacy fields or implementations into the new schema unless the rewrite plan explicitly requires them. At the same time, do not silently change old dataset identities or attribute historical results to the new feature definitions. Any retained legacy reader, fixture, or reproduction path is compatibility evidence, not the design template for the new product.

This repository is the rewrite root. Older repositories are reference or migration sources, never runtime dependencies. Use the installed `tape_data_product` package and `tape-product` CLI; do not introduce sibling imports or personal runtime paths.

Use small synthetic fixtures and fake clients for ordinary tests. Keep processing bounded by batches and fixed histories. Before a full external-data run, measure the exact production path on a representative sample, report resource and storage projections, and obtain explicit confirmation. Uploads, deletions, bulk acquisition, full-corpus builds, and publication require explicit task scope. Keep credentials, private catalogs, and detailed market-data rows outside Git.

Do not edit this file during ordinary implementation work. It is owner-maintained repository guidance and should change only when the user explicitly asks to revise it.
