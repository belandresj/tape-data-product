# Acquisition and canonical storage

The installed acquisition path starts with historical active US-stock reference membership, then unadjusted one-minute bars, the exact report screen, and complete paginated T/Q. Local files are sufficient; R2 publication is a separate explicit command. The original research bucket is private and is not available to repository users by default. The R2 adapter accepts the user’s own account endpoint, bucket and credentials. See [the reproduction guide](dataset-build.md) for the connected workflow.

`acquire reference --config reference.json --output reference` accepts a JSON configuration with `session_date` and `api_key_env` (default `MASSIVE_API_KEY`). `acquire minutes` adds `symbol`; it requests unadjusted minute bars for `[04:00,20:00)` ET. Run it once for each desired symbol, then concatenate the resulting JSONL minute records to screen a full historical reference universe. Pass repeated `screen --minute-receipt PATH` arguments for terminal minute acquisition stage receipts, one per reference symbol (including empty responses), in the same order used to concatenate the minute JSONL files. Their concatenated bytes must match the screen input exactly. For example, an invented `QUIET` reference member with no bars still needs an `acquire minutes` terminal empty-response receipt; include its directory with `--minute-receipt quiet-minutes` even though its JSONL contributes zero bytes. Complete historical population coverage also requires the adjacent verified `acquire.reference` stage to match the exact reference bytes and date. Detached reference files remain explicitly unverified even when supplied minute receipts cover every remaining member. The screener records `verified_minute_sources`, `missing_minute_sources` and `population_coverage_complete`; a detached minute file never proves full historical population coverage. A full population scan requires minutes for the entire reference universe; acquisition of a single symbol does not prove full population coverage. `fixture_pages` can instead name an ordered list of small provider-response JSON files; set `synthetic:true` for invented inputs. Paths resolve against the command working directory. Every acquisition writes a stage receipt last with effective parameters, installed implementation identity and output hashes.

`screen --reference reference/reference.jsonl --minutes minutes.jsonl --date YYYY-MM-DD --output screen` accepts reference JSONL records `session_date,symbol,type` and minute JSONL/Parquet records `symbol,window_start,transactions,volume,open,close,high,low`. `window_start` is an integer UTC nanosecond bar-start timestamp. The reference denominator includes all CS and ADRC members, even members absent from minutes. The eligible-source denominator counts reference members with at least one in-session, aligned minute with finite nonnegative transactions/volume and a finite positive close. Invalid OHLC bars remain in that denominator but break qualifying windows. Duplicate symbol/minute keys fail; missing minutes break consecutiveness.

Selection requires two consecutive valid OHLC bars, combined high/low log range `10000*log(max(high)/min(low)) >= 700`, combined reported transaction count at least 1600, and each minute at least 100. Dollar volume is not a screen. `selection.jsonl` preserves the first qualifying endpoint per member and source/configuration hash; `denominators.json` records both reference and eligible-source populations, candidates and qualifying-window counts. First-discovery verification requires the selected member's complete terminal minute receipt; detached minute inputs retain an observed endpoint with `discovery_verified=false`. Production T/Q rejects that unverified discovery. Discovery at the second minute's close is the earliest nominal bar-based observation time; historical vendor receipt latency is unavailable and is not fabricated. The SQLite membership/minute index is retained for inspection. This is the exact historical predicate reimplemented with bounded indexing, not a newly tuned universe rule.

`acquire tq` configuration names `selection` and optional `api_key_env`. It first verifies the screen receipt, processes each selected member sequentially, and creates `tq/session_date=YYYY-MM-DD/symbol=SYMBOL/{trades,quotes}.parquet`. Trades request `[04:00,20:00)` ET; quotes request `[03:55,20:00)` ET for initial NBBO state. Original integer SIP timestamps, vendor fields and same-timestamp input order are preserved. Out-of-order pages, unknown fields, missing required values, repeated cursors, incomplete pages and mismatched counts fail. Pair receipts retain the exact selected record, its canonical JSON digest and the selection-stage identity, so feature admission can reject another member's discovery or altered endpoints. Completion means the requested window terminated successfully, including legitimately empty streams; first/last event timestamps alone never prove coverage. Explicit narrow `coverage` windows are available only with `synthetic:true` and cannot be published as canonical market data.

`storage inventory --selection screen/selection.jsonl --pair-root tq-output --output inventory.jsonl` builds a streamable inventory with verified local pair paths and discovery metadata. Missing or duplicate selected members fail. `storage verify --pair PAIR_DIRECTORY` rechecks both full byte hashes, row counts, vendor schemas, timestamp bounds/order and coverage receipts. `--allow-synthetic` is explicit for demo fixtures.

`storage publish --pair PAIR_DIRECTORY --config storage.json` publishes both prevalidated streams with conditional PUT (`IfNoneMatch:*`). Existing objects must match SHA-256, byte length, rows and source/coverage metadata; their actual remote bodies are streamed and SHA-256 checked, and they are never overwritten. `storage stage --manifest pair.json --output NEW_DIRECTORY --config storage.json` downloads only that named pair and verifies actual body SHA-256 and row/schema/order evidence. R2 configuration has `endpoint_url`, `bucket` (default `massive-equities`), named `access_key_env`/`secret_key_env` (defaults `R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY`) and optional `max_stage_bytes` (default 512 MiB). Staging additionally preserves at least 3 GiB of free disk before downloading. The R2 client uses a 10-second connect timeout, 60-second read timeout and at most three retries. Credentials never enter receipts. Publication requires explicit operational scope; installation/demo do not publish or delete anything. A failed remote pair publication can leave one immutable stream present, which remains visible and must be inspected before retry.

Provider transport reads at most 8 MiB before JSON decoding and requests at most 4096 rows; JSONL records have the same byte cap. HTTP retries are bounded and apply only to transient connection failures, HTTP 429 and 5xx. T/Q encoding is O(T+Q), with a page and Arrow batch resident; Parquet validation uses 4096-row projected batches. Input order must already obey SIP order, so there is no hidden in-memory full-day sorting. Screening uses an 8 MiB SQLite cache, file-backed sorting and constant two-minute state: O(U log U) worst-case time and O(U) disk. Inventories reconcile with a disk-backed unique member index and one pair at a time. Transfers use one 1 MiB buffer. Real population/source completeness and historical reproduction require accepted external inputs; offline tests only validate implementation semantics. Full external runs require measured representative resource acceptance as described in the reproduction guide.
