# Endpoint/EW contract package

The installed `tape_data_product.contracts` package defines the new one-second base schema, 24 stored feature fields (27 queryable measurements including base ages), support schema, reason codes, bounded configuration, timing/transition rules, decimal admission checks, and structural interfaces. It does **not** calculate a production base/feature release. Existing legacy calculators/readers remain separate.

The schemas are `tape_base_1s_v1`, `tape_features_endpoint_ew_v1`, and `tape_feature_support_ew_v1`. Inspect exact field order/types/units through `BASE_SCHEMA`, `FEATURE_SCHEMA`, `SUPPORT_SCHEMA`; use `feature_registry()` / `query_registry()` for names and dependencies. Arrow field metadata stores units. Defaults are 30s/120s EW half-lives with 60s/300s startup; fixed-age p90 windows 60s/300s; 90% spread coverage, 80% other coverage; maximum trade reporting age 1s inclusive.

```python
from tape_data_product.contracts import DEFAULT_CONFIG, BASE_SCHEMA, query_registry, contract_identity
from tape_data_product.contracts.validation import validate_batch
print(DEFAULT_CONFIG.to_dict())
print(BASE_SCHEMA)
print([f.name for f in query_registry()])
print(contract_identity())
```

## Validation and identity

`FeatureConfig.from_dict` accepts only a complete, versioned configuration with known fields. Views/windows are immutable, unique, ascending and bounded to eight each; half-lives 1..86400s, startup 6..57600s, age windows 1..300s. Batch size is an operational setting and does not change feature meaning. Alternative half-lives require explicit startup settings; no optimization or automatic retuning occurs.

`contract_descriptor(config)` records configuration, schema hashes, registry, reason values, timing population constants, transition actions, and restart policy. `contract_identity(config)` hashes its canonical JSON. `implementation_identity()` separately hashes every installed contract module. Production releases must additionally identify their actual replay/calculation implementations and source inputs; the contract hash alone is not a run identity or numerical-verification result.

`validate_batch(batch, kind, config=..., previous_key=...)` checks exact Arrow schema including metadata, nonnull required fields, finite stored values, domains, masks, support constraints and ordered one-second member keys for at most 25,000 rows. Pass the returned key into the next batch. It rejects a member change; validate separate members separately. Complete-member row counts, companion joins, source receipts, file hashes, and independent numerical reconstruction remain writer/release responsibilities. Memory beyond the caller's Arrow batch is one row and fixed registry state, with O(rows × fields) work.

Reason masks are uint16. The named bits are SOURCE_UNAVAILABLE=1, SOURCE_UNVERIFIED=2, HALT=4, STARTUP=8, LOW_COVERAGE=16, NO_SUPPORTED_DATA=32, INVALID_CURRENT_VALUE=64, NO_OBSERVED_EVENT=128, MIDPOINT_AGE_LOWER_BOUND_ONLY=256, CONTINUITY_BREAK=512, ZERO_RETURN_VARIATION=1024, ZERO_SPREAD=2048. Unknown bits are rejected. A published value is nonnull exactly when its mask is zero. Historical summaries do not inherit all current-input failures. Ratio reasons follow their historical components. Low coverage is assessed only after startup; zero supported history uses NO_SUPPORTED_DATA rather than manufacturing a numerical estimate.

## State transitions

The executable action catalog is `policy.TRANSITIONS`. The scope below specifies how future reducers must apply it. Source-continuity IDs are monotonically increasing per member and never reused. Quote and trade continuity are independent of EW startup clocks.

| Event | Price/return and event origins | EW state | Exact-age history |
|---|---|---|---|
| Session start at 04:00 ET | Seed latest prevailing quote from verified preceding 300s, including an invalid state; no pre-session trade seed, no synthetic 04:00 return endpoint; midpoint comparison seed is not a change | Zero sums/weights, start source-specific startup clocks | Empty windows; observation origin cannot precede 04:00 |
| Reporting stratum at 09:30/16:00 or discovery | No reset; trade condition population changes at the exact SIP stratum boundary | Retain | Retain |
| Ordinary invalid quote | Endpoint is unavailable while invalid; no older-good substitution; clear midpoint comparison/change origin; quote-event timestamp remains observed | Retain and decay; remove only unsupported return/exposure contributions | Current midpoint age unknown; append unsupported wall slots without clearing historical window; quote-event age can stay known |
| Valid quote after ordinary invalid state | Seed midpoint comparison and observation origin; first recovery is not a midpoint change | Retain | Midpoint exact age remains unknown until a later observed change; lower bound advances |
| Bad size on one side | Only that side's size is unavailable if price remains valid | Other families retain support | No age reset |
| Known ineligible/late trade | No activity contribution, no eligible-trade age refresh; it does not represent missing feed time | Reliable activity exposure remains positive | No reset |
| Unknown trade eligibility, localizable to one second | That second's common count/share/dollar population has zero supported exposure; do not keep partial totals with a full denominator. Exact trade age loses its origin until the next definitely eligible event | Decay activity with no contribution for that second; quotes unaffected | Trade window retains older samples but current uncertain-age slots are unsupported |
| Known quote feed gap | Clear prevailing quote and return continuity; increment quote continuity at onset; clear quote/midpoint event origins | Decay quote-family sums and usable weights; possible weights and startup clock advance; suppress quote-family publication during outage | Reset quote and midpoint age windows; do not advance their new startup while outage remains active |
| Known trade feed gap | Clear trade origin and increment trade continuity; quotes unaffected | Same retain/decay policy for activity only | Reset trade-age windows |
| Feed recovery | Require a new usable quote to seed price, a structurally accepted quote for quote-event age, and a new eligible trade for trade age. No return crosses a changed continuity segment | Resume contributions without restarting EW startup; historical publication resumes when source/coverage gates pass, even if the newest numerical sample is unusable | Start new age-window wall slots at first fully observed recovery second; lower bounds/event origins seed only when justified |
| Accepted halt overlaps a second | Close whole second; clear both source origins and lag; increment continuity so no pre-halt return bridges it. Events in closed seconds do not seed recovery | Clear both EW histories on entry; no possible exposure/startup during halt | Clear all age windows |
| First fully open post-halt second | Accept only new post-closure events; a quote/trade at its left edge belongs to this second | Start clocks/sums from empty; apply full 60s/300s startup | Start fresh wall slots; full window maturity required |
| Coverage below threshold | No additional observation reset | Keep all decaying state; output null until gates recover | Keep fixed slots and supported samples |
| Batch/file boundary | No semantic effect | Retain | Retain |
| Session end | Publish endpoint 20:00 for [19:59:59,20:00); then discard member state | Never carry across dates | Discard |

For a feed gap ending inside a second, base integrals can retain explicitly known supported post-recovery exposure; source status describes endpoint observation trust. The age-window restart convention above conservatively begins at the next full observed second. Current exact ages can be known earlier if a qualifying post-gap event is actually observed. Precise gap overlays plus IDs disambiguate resets; physical grid gaps are corruption, not inferred outages. Source IDs change at onset, not again merely because recovery occurs. Multiple declared breaks in one second increment IDs separately.

An unknown quote condition that could change price validity makes that prevailing price unknown until a usable update restores it; it is an ordinary semantic invalid state, not an inferred feed outage. Unknown fields/codes are preserved and counted through bounded versioned admission. Semantics known to affect only size must not erase price. Unknown correction scope, conflicting keys, untrustworthy time or changed identity cannot be silently localized: stop the affected member/dependency and require a verified rebuild. Recovery from a resource guard is never automatic.

## Clock, validity and numerical construction

Rows summarize `[t−1s,t)`; event timestamps equal to t belong to the next row. Use SIP time to assign activity; participant time only gates age `0 <= SIP−participant <= maximum`. RTH is [09:30,16:00) by event SIP time. Accepted condition sets are (0,3,14,36,37,41,60), with 12 additionally allowed outside RTH; causal original correction payloads are (0,7,8). Action records and correction payload 1 remain excluded. Unknown condition eligibility is uncertainty, not a known zero. The original condition decoder is a migration reference; downstream semantic implementation must retain its accepted quote-condition mapping without importing historical engines into this contract layer.

A return at t uses m(t−5s), m(t), valid endpoints and no intervening declared gap/halt. Intermediate invalid prices alone do not invalidate it. The first possible return uses endpoints one and six. `endpoint_return` uses log1p for nearby prices and a log difference for extreme ratios. It does not inspect subsecond paths.

TWAPs use common valid two-sided price exposure. Spread support requires otherwise valid finite positive bid/ask and ask>=bid. Equal prices contribute zero spread with positive exposure. An explicit lock flag with unequal positive prices leaves numeric midpoint usable if otherwise valid, but spread is unsupported due to the contradictory spread state; never coerce it to zero. Size support requires a positive finite own-side normalized size and valid two-sided prices, independently of the other size. Quote-event age uses a structurally accepted timestamp regardless of unusable prices/sizes. Midpoint age clears on any invalid midpoint transition, including zero-duration invalid/recovered ties.

For each half-life h, lambda=2^(-1/h). Advance supported numerator and usable denominator by lambda then add current supported contribution; also advance possible denominator even when input is unsupported. Possible exposure starts at row one, possible return weight at row six after estimator reset. Known feed gaps and their lag-recovery slots never restart or remove possible return weight. Return moments share exactly the same admitted returns and weights. Source-family startup advances each wall row outside halt, including represented gaps, independently of usable coverage. Use deterministic chronological update order; chunks cannot reassociate sums.

Coverage is usable/possible, unavailable when possible=0. Compare `usable >= configured_threshold * possible` without an epsilon threshold relaxation. Structural invariants enforce usable<=possible; roundoff controls belong in accumulation, not a hidden looser admission threshold. Startup failure is STARTUP; after maturity positive-but-insufficient support is LOW_COVERAGE; no support is NO_SUPPORTED_DATA. Current ordinary invalid primitives do not blanket-gate historical estimates; declared current outages do. Current active halt always prevents publication.

Exact-age p90 retains H wall slots and a sorted supported-value list: O(H) insertion/deletion (list shifts), O(1) interpolation, O(H) memory; H<=300. Unknown ages and midpoint lower bounds occupy unsupported slots. Maturity is H elapsed slots since applicable reset and coverage requires ceil(fraction*H) known samples. No event resets age-window maturity merely because an ordinary value is invalid.

Float64 mathematical reconstruction tolerances are rtol=1e-10, atol=1e-12 in output units; common-support TWAP identity uses rtol=1e-12, atol=0. Keys, counts, durations, masks, exact decimal shares and schema/config identities compare exactly. Same chronological binary64 updates across batch sizes must give identical values; independently computed reference arithmetic uses the tolerances. Tolerance never authorizes clipping a source spike or adding a denominator epsilon.

Downstream EW moments must use exponent-scaled nonnegative sums (binary64 mantissa plus integer exponent) for U1/U2/W so long decay does not underflow U2 before taking a square root. Track whether any positive return has been admitted since the last actual estimator reset separately from numerical magnitude. An all-zero mathematical history gives RMS=0 and undefined participation. A nonzero history rounded below the representable output range may give zero at float64 precision, but must not acquire ZERO_RETURN_VARIATION merely due to underflow. Calculate A²/Q and sqrt(Q) from scaled state; reject unexpected overflow/domain contradictions. This is the implementation obligation for Phase 3, not a claim that its numerical engine exists. The bounded session and view count also bound exponent state.

## Source precision and units

The base share type is decimal128(38,9). `source.share_units` converts decimal text losslessly to scaled integer units, checks every nonzero digit, and rejects overflow/more precision instead of rounding. `add_share_units` checks totals; `shares_from_units` is independent of Python's ambient Decimal precision. Float-only historical values can establish exact quantities only where their exact binary value is representable at this scale (e.g. 0.5, not evidence that float 0.1 was originally the decimal text "0.1"). Preserve original decimal strings when present.

Massive documents fractional trade size as decimal text but gives no universal maximum scale on the referenced endpoint page. Therefore scale 9 is a supported lossless input contract, not a claim that every archived member is admitted. The Phase 2 source check must inspect every consumed input quantity and fail the affected build before completion if its precision cannot be preserved. More-precise source data requires a versioned schema extension, not exclusion of otherwise eligible trades. This inspection runs inside bounded replay/admission; no speculative full-corpus scan is required by this module.

Massive documents current stock quote sizes in shares and a November 2025 transition/regeneration of historical flat files. `SourceUnits` requires identity-bound evidence and allows either already-normalized shares (factor 1) or verified member-specific round lots. It rejects guessed/unknown units and double conversion of share-denominated data. The caller must establish the evidence; a syntactically valid hash alone is not proof.

Sources checked during contract design: [stock trades](https://www.massive.com/docs/rest/stocks/trades-quotes/trades), [stock quotes](https://www.massive.com/docs/rest/stocks/trades-quotes/quotes), [size-unit transition](https://www.massive.com/blog/change-stocks-quotes-round-lots-to-shares). No statement here certifies the units/precision of uninspected canonical objects.

## Interfaces, completion and restart

`interfaces.BaseBuilder` and `FeatureBuilder` are typing protocols, not runnable builders. Planned calls are `build_base_partition(source_pair, member_context, output, *, config, batch_size=4096)` and `build_from_base(base_partition, output, *, config, batch_size=4096)`, returning `BuildResult(member_identity, contract_identity, manifest_path, rows)`. Config and schemas are shared; raw access is absent from the feature-builder inputs. Production entry points are added only when implemented. Validate batch size 1..25000 and use installed-package resources.

The first production restart policy is completed-member reuse or reconstruction from session start. `CompletedMember` binds member, inputs, semantic contract, implementation, manifest and rows; exact mismatch prevents reuse. Callers must actually verify manifest bytes and every companion before constructing a trusted completion record. An interrupted member has no completion marker and is never reused as valid output. A new attempt uses separate bounded scratch space; never silently overwrites immutable canonical data. Source/resource failures require inspection, not automatic retry.

No persisted partial EW/replay checkpoint format is implemented or accepted in V1. A reader needing an estimator variation must process base from session start, while a feature query reads the completed feature table without resetting values. Supporting arbitrary checkpoints later requires a new protocol containing all numerical scaling state, lag/age histories, source ordering/cursors and committed output position; a diagnostics row is not a checkpoint.

Required member manifest envelope for downstream writers: `manifest_version`, `member` (symbol/session), `coverage` (full or explicit prefix, start/end/expected rows), `inputs` (immutable hashes/bytes, admissions and control identities), `source_units` (declarations/evidence), `contract_identity`, `implementation_identity`, `outputs` (relative paths/hashes/bytes/rows/schema hashes), `validation` (integrity vs independent reconstruction evidence), and `complete=true`. Serialize canonical JSON; bound the manifest to 1 MiB; reject absolute output paths and traversal. Completion appears atomically only after ordered keys, cross-table companions, declared counts, source stability and output checks pass. Ledger/catalog aggregation is on disk, not a corpus-sized manifest.

Discovery/control metadata records nominal discovery endpoint and provenance separately from actual received time. Expose `eligibility_basis`: nominal verified source endpoint versus measured receipt. In receipt mode eligibility starts at max(nominal endpoint, actual receipt), evaluated at each row endpoint; missing receipt means unavailable in that mode. Nominal mode can reproduce a historical selection but must not claim measured live delivery. Discovery never gates raw measurement construction or resets histories. Halt overlays retain historical/ex-post status and available knowledge timestamps; retrospective information cannot be relabeled as live-known.
